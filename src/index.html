02 / How arnx works

Investigate the change.
Keep the checks that matter.

  1. 01

    Setup

    Understand the project, propose a Docker test environment, and run the existing suite. Inspect the configuration before approval.

    arnx setup
  2. 02

    Review

    Investigate the diff, generate targeted tests, and run them. Read the failures, open questions, and coverage gaps.

    arnx review
  3. 03

    Accept

    Validate meaningful findings and keep their tests. You or your coding agent make the fix.

    arnx accept <id>
  4. 04

    Check

    Rerun accepted regression tests in Docker without new model calls. Review and commit the tests with the fix.

    arnx check

03 / Why executable evidence matters

A suspicion needs a test.
A failing test needs your judgment.

Inspect the behavior

A review comment identifies a possible problem. An executed test gives you inputs, an expected result, and a failure you can investigate.

Validate the assumption

A test can misunderstand intent, depend on a brittle fixture, or fail at setup. Repetition and a second model do not replace developer review.

Check it again

Accepted tests remain local files. Use arnx check after the fix and on later changes, with no additional model inference cost.
