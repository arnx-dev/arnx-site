02 / How it works

Your judgment.
Your agent. A checked fix.

From a change you want to understand
to a test worth keeping.

  1. 01

    Set up once

    arnx proposes a Docker environment and runs your existing suite. Inspect the projects, services and exclusions before approval.

    arnx setup
  2. 02

    Review a change

    Inspect failing tests, the second-model assessment, open questions and what was left untested.

    arnx review
  3. 03

    Decide what matters

    Mark findings real, intended or noise. Answer questions about behavior only you can decide.

    You make the call
  4. 04

    Accept useful tests

    Keep selected tests before fixing the code. Answers that settle intent can become tests too.

    arnx accept <id>
  5. 05

    Give your agent the fix

    Print a handoff with accepted findings, answers and tests. You or your coding agent change the production code.

    arnx prompt <id>
  6. 06

    Check. Then keep.

    Run accepted tests in the approved sandbox. Inspect and commit the tests together with the fix.

    arnx check

Where does arnx fit in a PR workflow?

Run the CLI on your change before opening a PR or during review, before merge. arnx generates and runs tests for suspected bugs. You inspect the evidence, accept useful tests, and hand the fix prompt to your coding agent. Then arnx checks the fix with those tests. The current pilot is a developer-run CLI workflow; it does not post PR comments or provide a hosted GitHub check.

What does “bring your own model” mean?

Configure supported models for arnx's review workflow using your own provider API keys. You pay those providers directly. Model choice depends on the supported provider and role; BYOM does not mean every model or a local model can run in arnx. Selected code is sent to your configured providers.

Is arnx open source?

Yes. The arnx review package is MIT software. You can inspect the harness, and accepted tests remain ordinary, editable files in your repository. Open source does not make model-provider API calls free.

Does arnx fix my code?

You or your coding agent make the fix. arnx retains accepted tests, prepares the fix prompt and runs the tests to help you check the result.

Is a finding always a bug?

No. A repeated failure and a second-model assessment give you evidence to inspect. The test can still make a wrong assumption. You decide whether the behavior is a bug, intended, or noise.

Does a clean result mean the change is correct?

No. Read open questions and coverage gaps. A passing arnx check means the accepted tests passed in that environment. Questions alone can still leave a review with exit code 0.

Where does my code go?

Tests run in local Docker containers. Selected code goes to configured model providers. Recognized secrets are filtered; inspect .arnxignore for repository data and sensitive files. Read accepted tests before running them through your own tooling.

What does it cost?

The arnx package is MIT. You pay your model providers directly. In the documented Opus pilot, setup, review and acceptance totaled $5.36 in reported model spend. The fixing agent's cost was separate and unrecorded. Each arnx check made no model calls. This is one example, not a typical-price estimate. We'll agree a spend cap before your first run.

How do I get it?

Request a pilot invitation below. Selected participants receive instructions for the chosen pre-release build. Docker and model API keys are needed; an existing coding-agent subscription should not be assumed to cover API calls.
