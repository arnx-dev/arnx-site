Compare / CodeRabbit

arnx and CodeRabbit do different jobs.

One reviews the pull request. One tests the change before it.

CodeRabbit is a hosted AI reviewer that comments on pull requests for a whole team, in any language, on the common code hosts. It also has an IDE extension and a CLI. arnx is an open-source CLI that a developer or their coding agent runs on their own machine once a change is finished. It writes tests for what looks broken, runs them in Docker, reruns each failure on the code before the change, and reports the tests that failed.

So the question is rarely which one to pick. CodeRabbit covers every pull request with review comments. arnx covers one change at a time with executed tests, in three languages, and lets you keep the useful tests as regression checks. They fit at different points of the same workflow.

Both products can generate tests. The difference is the default. CodeRabbit writes tests when you ask and its review output is comments. arnx's only output is tests it ran.

When CodeRabbit is the better choice

  • You want every pull request reviewed for a whole team without anyone running a command.
  • Your code is not Python, JavaScript, TypeScript or Rust. CodeRabbit states it works with all programming languages.
  • You want comments in the pull request, on GitHub, GitLab, Bitbucket or Azure DevOps, with fixes you can apply there.
  • You want linters and security scanners in the same pass. Its architecture page describes 50+ static analyzers, linters and SAST tools.
  • You want a reviewer that learns team preferences from replies, and links to issues in GitHub, Jira or Linear.
  • You do not want to run Docker or manage model keys. It is a managed service with per-seat pricing, and free Team features for open-source projects.

When arnx is the better choice

  • You want a finding you can run: a test, its failure, and whether it passed before the change.
  • You want to check a coding agent's work before a pull request exists. The arnx skill lets the agent run the review and fix the code against the accepted tests.
  • You want to keep the tests. Accepted tests are pinned and rerun by arnx check on later changes with no model calls.
  • You want open source (Apache-2.0), your own model keys, prompts you can edit, and tests that run only on your machine.
  • You pay per review, not per seat, and set the cap yourself.

Using both

Run arnx on your machine when the change is done: triage the findings, fix what is real, and commit the accepted tests with the fix. Then open the pull request and let CodeRabbit review it for the team. arnx does not replace a pull request reviewer, and it posts nothing there. One example of arnx on a repository that already used an automated pull request reviewer is the Hummingbot case study.

What arnx does not do

  • Three languages only: Python, JavaScript and TypeScript, and Rust (early). It works best on single-package Python and TypeScript repositories.
  • It needs Docker and a project with an existing test suite. Code in no such project is reported as not reviewed. Tests that run only in a browser are not run.
  • A review takes minutes, not seconds, and the first one also sets up the test environment (it stops at 10 minutes). Changes over 200 KB are refused; review a long branch in parts.
  • It posts nothing to a pull request. The report is a local file.
  • Findings can be wrong. A failing generated test shows an assertion fails, not that the code is wrong, and the second model can agree with a wrong test. Our own counts are in AI code review findings on unfamiliar repositories. Deciding stays with the developer.
