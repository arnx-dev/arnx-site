Owner-run case study

From a finding
to a checked fix.

Your agent fixes the code. arnx runs the tests that check it.

On a real Python pipeline backed by Postgres, arnx generated tests for suspected bugs, the owner judged the findings and answered questions, and their coding agent made the fixes. The final sandbox check recorded 54 passed, zero failing and one skipped. The accepted test files stayed unchanged after acceptance.

This is a summary of a recorded owner-run case, not a public replay bundle. Private source, generated test bodies, and raw execution logs are not published.

The change

A token-callout prediction pipeline spanned 12 commits and 29 files, with 3,311 lines added. It involved hourly snapshots, polling, model training, live scoring and advisory messages. arnx set up five projects; Postgres was available to the Pipeline service tests, and the owner approved the environment.

The reviewer was Claude Opus 5.5; part hunters used Claude Haiku 5.5, with gpt-6.1-sol as second hunter. The second opinion used GLM-5.3-Flash via River, with gpt-6.1-sol as fallback. A dropped connection was handled by resuming the review.

See the failure.

Tests reproduced an inverted Gini calculation, callouts lost beyond a 2,000-item page cap, stale prices used in evaluation and training folds that split the same hour. Where behavior needed a database, tests ran against Postgres in the approved sandbox.

The owner marked 18 findings real, including four the second model had disputed. Those are finding marks, not a count of distinct bugs.

Answers about intent mattered too. The owner wanted the price at the time a signal fired. A generated test showed that the implementation didn't match that answer, so arnx retained it as a failing test. A response about callout ID types didn't settle intent; that question stayed open and produced no test.

Check the fix.

arnx accept retained tests and wrote a fix prompt containing their locations, the findings, owner answers and the unresolved question. The owner's coding agent received that prompt, with instructions to change product code and leave the accepted tests intact.

The agent changed nine product files. arnx then ran the accepted tests in the approved environment, including Postgres.

Final accepted-test sandbox check
Project Passed Failing Skipped
API service 12 0 1

Total 54 0 1

The skipped test corresponded to a finding not confirmed. Accepted test files were unchanged after acceptance. A temporary schema-path workaround was removed after an arnx acceptance-path fix; the check still passed afterward.

Keep the test.

The product fix was accompanied by regression tests in the repository. The tests used to expose the accepted failures helped check the changes. These remain ordinary, editable test files, ready to run as the project evolves.

What this establishes

The complete workflow worked on one real, owner-judged development change. The branch had been used to tune arnx, and the run crossed builds as acceptance defects were repaired.

Two known issues were missed. The owner's marks do not establish a general precision rate.
